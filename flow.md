# Observation and world lifecycle

1. Open CHRONOS: read chronos.colony; strictly validate/migrate schema 2/3 or resume schema 4, or create founders. A corrupt save stays protected while a temporary world runs. Earlier chronos.world is untouched.
2. Display the initial world and start the embedded worker. It advances two ticks per second, predicts one next snapshot and publishes timestamped state. Rendering interpolates independently of UI updates. Worker failure resumes a retained checkpoint through the same local loop. No observation action pauses it.
3. Drag/zoom or choose a camera. Open one panel: Residents, Settlement, City mind, Chronicle or World. Settlement filters functional building types; City mind shows districts and actual pending/evaluated learning decisions. Selecting a person/place reveals current details; Locate focuses it. Follow tracks a living resident, with the mobile panel dismissed. Manual camera interaction cancels follow. A deceased selected resident shows a history message.
4. Worker checkpoints are retained on the page; autosave writes approximately every ten seconds and on page hide. Before the first schema-4 write, chronos.colony.before-districts preserves the original raw save; an earlier before-river-city backup remains untouched. A raw-save compare guards concurrent tabs. A conflict or backup/storage failure blocks silent replacement; export remains available.
5. Return after sleep/closure: recover nonnegative elapsed time, including sub-tick fractions, capped at seven real days. Budgeted batches show progress and save checkpoints whose logical timestamps preserve outstanding life across another reload.
6. Export downloads a recent authoritative checkpoint; its timestamp preserves subsequent elapsed life for recovery. Import validates before confirmation, and cancellation preserves the current world. Confirmed replacement starts the imported world. New world uses a fresh seed only after confirmation. Export first to retain a world being replaced.
7. Invalid JSON, oversize inputs and bad references show an error without replacing state. Unavailable/full storage keeps the world in memory and directs the observer to export. Graphics failure shows a readable recovery message; observation panels and saving continue.

There is no login, external inference or hosted backend in these flows. Fullscreen is optional; native denial shows a message. Native dialogs retain focus behavior. N/B/L/J/W/F/1/2/3/4/H/Escape are observation shortcuts; inputs/buttons retain ordinary keys. Temporary preview servers are stopped after QA; public source distribution is distinct from website hosting.
